## 二、作品简介（三档字数，按表单限制选用）

### 100 字版

Awesome Atlas 把 678 条精选清单折成一张可用键盘操作的「清单地图」：27 个分类按规模铺成面积图，可下钻到单条清单；另配关系图谱、检索榜单、生态时间轴与数据洞察四种视图。纯静态、零依赖，手机与桌面同源，国内网络直开。

### 300 字版

Awesome 生态有 600 多条清单，但它的入口始终是一篇几万字的 Markdown——想找「某个方向还有哪些清单」「哪些项目已经三年没更新」，只能靠 Ctrl+F。

Awesome Atlas 把这篇文章重建为五视图的可视化工作台：分类地图按条目数铺面积、可逐层下钻；关系图谱把分类与清单的从属关系画成径向结构；检索榜单支持排序、分页、收藏与多条件过滤；生态时间轴还原上游 24 次修订与仓库活跃度；数据洞察给出分类权重、健康分分布与停滞清单。全站支持中英切换、命令面板（`Ctrl+K`）、URL 分享当前视图，以及完整的键盘操作与 4.5:1 以上对比度。

技术上它是一套可复现的数据管线：抓取上游 README → GitHub GraphQL 全量补全 673 个仓库 → 差分出历史 → 生成静态数据。产物是 4 个静态文件，零构建、零依赖、零第三方运行时请求，国内网络可直接打开。

### 800 字版

**问题**：`awesome` 系列是开发者最常用的「清单的清单」。主仓库累积了 678 条条目、27 个分类，但它的唯一界面是一篇几万字的 Markdown。你无法按星标排序，无法知道某个分类整体是否还活跃，无法判断一条清单是「刚收录」还是「三年前就在」，更无法把「我筛出来的这一屏」发给同事。

**做法**：Awesome Atlas 把这篇文档当作数据库重建，而不是重排。管线分四步：解析上游 README（保留锚点、父子层级、原始链接）→ 用 GitHub GraphQL 批量补全 673 个仓库的星标、Fork、语言、归档状态与最近推送 → 对 24 次上游修订做差分，得到新增 / 移除 / 改链 → 生成完全静态的 `catalog.json` 与 `catalog.js`。所有数字都能用脚本重新算一遍，`validate.mjs` 会用独立方法重新统计原始 README 并逐项比对。

**五个视图**解决五类问题：
1. **分类地图**——面积代表条目数，颜色代表平均健康分，点击下钻到单个分类；
2. **关系图谱**——径向布局呈现「分类—清单」结构，可直接点分类聚焦；
3. **检索榜单**——星标 / 名称 / 更新时间排序，配合语言、归档、收藏、健康度过滤；
4. **生态时间轴**——24 次修订与仓库推送年份叠加，一眼看出生态冷热；
5. **数据洞察**——分类权重、健康分分布、语言构成、停滞与归档清单聚合。

**体验差异化**：全站只有纸白、墨黑与一个朱红强调色，0 圆角、无渐变文字、无 emoji 图标；颜色从不单独承担信息编码，面积、位置、文字标签同时编码。支持 `Ctrl+K` 命令面板、`/` 聚焦搜索、方向键切标签、表格行回车打开详情、命令面板焦点陷阱与归还；深浅色主题各有一套数据色阶。移动端底部导航的所有触控目标实测 ≥ 44px。

**工程可信度**：数据层 95 项断言、真实浏览器 127 项断言全部通过，axe-core 在桌面 / 移动 / 深色 / 命令面板四种状态下 0 违规；CI 同时跑数据层与浏览器层。部署包不含预览产物与内部缓存。

**真实性边界**：星标、Fork、最近更新是采样时点快照，不是实时数据；健康分是本站定义的启发式指标（活跃度 + 维护状态 + 生态信号），不代表项目质量评级。数据源为 `sindresorhus/awesome`（CC0-1.0），本站保留原始名称与链接，中文译文为增补内容；代码以 MIT 发布。

## 三、差异化亮点（填「作品亮点」时逐条用）

1. **不是又一个 awesome 列表站，而是把列表变成可查询的数据集**——每个数字都能被脚本复算。
2. **五视图各解决一个问题**，不是同一个表格换皮：面积图看结构、图谱看从属、榜单做检索、时间轴看演化、洞察看分布。
3. **零依赖的工程克制**：4 个运行时文件、无框架、无构建、无第三方请求，首屏在普通网络下 2 秒级打开。
4. **可访问性不是口号**：对比度、触控尺寸、键盘路径、焦点管理全部写成断言，并用真实浏览器逐控件点击验证。
5. **可复现**：一条命令重建数据，一条命令复跑全部校验，报告随仓库更新。
